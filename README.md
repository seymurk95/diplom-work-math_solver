# Автоматическая проверка математических решений с помощью Lean 4

Данный репозиторий посвящён пайплайну, который берёт математическую задачу, получает её пошаговое решение от небольшой языковой модели и затем **формально проверяет** результат в системе доказательств Lean 4.

---

## Идея пайплайна

Работа разбита на три независимых этапа. Каждый этап — отдельный скрипт, который читает файл предыдущего этапа и записывает свой:

```
qwen.py  ──►  qwen_solutions.txt  ──►  kimina_autoformalizer.py  ──►  statements.json  ──►  kimina_prover.py  ──►  prover_results.json
(решение)                              (формализация + проверка                           (доказательство + проверка
                                        компиляции в Lean)                                  в Lean + аксиомы)
```

1. **Решение.** Небольшая модель решает задачу и записывает шаги в строго заданном формате (`Problem / Solution / Step N / Answer`).
2. **Автоформализация.** Условие и решение переводятся в формальное утверждение на Lean 4. Скрипт сразу проверяет, что оно компилируется, и подготавливает его для следующего этапа (заменяет `:= by sorry` на `:= by`).
3. **Доказательство.** Модель-доказыватель пишет доказательство, а Lean его проверяет. Засчитывается только то, что реально принял компилятор.

---

## Используемые технологии и модели

Все модели запускаются локально через OpenAI-совместимый сервер (по умолчанию `http://localhost:1234/v1/chat/completions`, например LM Studio).

1. **qwen3.8-4b-distill(https://huggingface.co/empero-ai/Qwen3.8-4B-Distill-GGUF)** — генерация пошагового решения задачи.
   - **Роль:** получить решение в формате, где каждый шаг — явное равенство или логический переход, пригодный для перевода в Lean.
2. **[Kimina Autoformalizer 7B](https://huggingface.co/AI-MO)** (`ai-mo.kimina-autoformalizer-7b`) — перевод условия задачи в формальную теорему на Lean 4.
   - **Роль:** выдать утверждение с именем `my_favorite_theorem` и заголовком `import Mathlib`.
3. **Kimina Prover Distill 8B** (`kimina-prover-distill-8b`) — написание доказательства для готового утверждения.
   - **Роль:** по формальному утверждению построить доказательство тактиками Lean 4.
4. **[Lean 4](https://lean-lang.org/) + [Mathlib](https://leanprover-community.github.io/)** — проверка. Запуск через `lake env lean` из проекта `my_project`.

## Структура проекта

- `qwen.py` — скрипт этапа 1. Отправляет задачи из списка `TEST_PROBLEMS` модели Qwen, вырезает блок рассуждений `<think>...</think>`, принимает ответ только если он завершён (`finish_reason = stop`, есть `Solution:` и `Answer:`) и записывает результат в `qwen_solutions.txt`.

- `kimina_autoformalizer.py` — скрипт этапа 2. Для каждого блока из `qwen_solutions.txt` просит Autoformalizer сформулировать теорему, извлекает Lean-код из ответа, компилирует его и сохраняет в `statements.json`. Файлы `.lean` складываются в папку `kimina_proofs`.

- `kimina_prover.py` — скрипт этапа 3. Для каждой задачи из `statements.json` делает до `ATTEMPTS` независимых попыток доказательства и проверяет каждую в Lean.

- `qwen_solutions.txt` — результат этапа 1: решения задач в формате `Problem / Solution / Answer`. Блоки разделяются строкой `---`.

- `statements.json` — результат этапа 2. Для каждой задачи хранит условие, решение Qwen, код от Autoformalizer, флаг `compiles` и готовое для Prover утверждение `prover_statement`.

- `prover_results.json` — итог этапа 3: статус каждой задачи (`proved`, `not_proved` или `no_statement`).

---

## Как устроена проверка

Главная часть проекта — это не генерация, а защита от ложных «доказательств». В `kimina_prover.py` реализованы следующие проверки:

- **Ответ не должен быть обрезан.** Если `finish_reason` не равен `stop` или рассуждения не уложились в лимит токенов (`MAX_TOKENS = 8096`), попытка не засчитывается.
- **Утверждение берётся из файла, а не от модели.** Скрипт берёт только тело доказательства (всё после `:= by`) и подставляет его под исходное утверждение из `statements.json`. Если Prover переписал формулировку, это выводится как замечание, а доказательство всё равно проверяется под *оригинальное* утверждение.
- **Lean должен принять код.** Любая ошибка компиляции означает, что попытка не засчитана.
- **Проверка аксиом.** После теоремы добавляется `#print axioms`. Допустимы только стандартные аксиомы `propext`, `Classical.choice` и `Quot.sound`. Если в доказательстве остался `sorry`, он проявится как `sorryAx`, и попытка отклоняется.

Если за все попытки доказать утверждение не удалось, скрипт пишет «не доказано», и это означает «неизвестно», а не «ответ неверен».

## Пример работы

Задача: *Найти производную функции f(x) = x² · sin x.*

Qwen возвращает решение через правило произведения:

```
Step 1. Apply the product rule: (uv)' = u'v + uv', where u = x² and v = sin x.
Step 2. Compute derivatives: u' = 2x, v' = cos x.
Step 3. Substitute into the product rule formula: f'(x) = 2x · sin x + x² · cos x.

Answer: 2x·sin(x) + x²·cos(x)
```

Autoformalizer превращает его в утверждение на Lean 4:

```lean
import Mathlib

theorem my_favorite_theorem (f : ℝ → ℝ) (hf : f = fun x => x ^ 2 * Real.sin x) :
    deriv f = fun x => 2 * x * Real.sin x + x ^ 2 * Real.cos x := by
```

Prover находит доказательство, Lean его принимает, аксиомы стандартные — в `prover_results.json` задача получает статус `proved`.

## Запуск

1. Установить Lean 4 и создать проект с Mathlib (в скриптах он называется `my_project`).
2. Запустить локальный сервер моделей и загрузить нужные модели.
3. Установить зависимость: `pip install requests`.
4. Поправить пути и имена моделей в блоке `# ---- настройки ----` в начале каждого скрипта (сейчас там указаны пути вида `C:\dev\diplom\...`).
5. Запустить скрипты по порядку:

```
python qwen.py
python kimina_autoformalizer.py
python kimina_prover.py
```

Полезные параметры в `kimina_prover.py`:

| Параметр | Что делает |
|---|---|
| `ATTEMPTS` | число независимых попыток на задачу |
| `MAX_TOKENS` | лимит токенов на ответ Prover |
| `USE_SOLUTION_HINT` | если `True`, решение Qwen добавляется в запрос как подсказка |
| `ONLY_IDS` | список номеров задач для запуска (пустой список — все задачи) |

## Ограничения

- Lean проверяет, что доказательство верно **для записанного утверждения**. Совпадает ли это утверждение по смыслу с исходной задачей, зависит от качества автоформализации и автоматически не проверяется. Формулировку стоит просматривать глазами.
- Сейчас проверяется итоговое утверждение, а не каждый шаг решения Qwen по отдельности.
- Пока протестировано на одной простой задаче (производная произведения).
